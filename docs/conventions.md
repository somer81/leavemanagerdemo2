# Conventions

> Set at bootstrap 2026-11-14. Only rules that are real: every rule here should be
> either enforced by tooling (preferred) or checked in review. Aspirations don't belong here.

## Language
- Chat language (interviews, sessions): English (`en`)
- Document language (docs/, specs, plans, ADRs, review and verify reports): English (`en`)
- Always English (protocol, not prose): ANEW core files, template headings and field labels,
  `Status:` values (Draft / Approved / In progress / Shipped), `Approved by / on:`, `Source:`.
- Code identifiers, branch names, commit messages: English.
- Agent messages (handoff summaries, refusals, `Next:` lines): chat language; command names, file
  paths and protocol fields verbatim.

## Language & framework versions
- Node.js **26 LTS** (`engines.node: ">=26 <27"`, `.nvmrc` = `26`). npm workspaces.
- TypeScript, `strict: true`, ESM everywhere (`"type": "module"`).
- React + Vite (web), Fastify (api), zod (validation), Vitest + Testing Library + jsdom (tests),
  ESLint + Prettier. Exact versions are pinned in the lockfile by the walking-skeleton spec; a
  major upgrade is its own spec.
- TypeScript is pinned to **6.0.x**: `typescript-eslint` 8.x requires `<6.1.0`. Moving to TypeScript 7 is its own spec (plan 0001, Risk 1).
- The API runs its TypeScript directly via Node 26's built-in type stripping (no `tsx`/build step), so
  code must be erasable syntax only (`erasableSyntaxOnly`): no `enum`, `namespace` or parameter properties. Imports use `.ts` extensions.
- SQLite via Node's built-in `node:sqlite` (preferred: no native build). The first spec that persists data confirms it, otherwise an ADR picks the driver.

## Naming
- Domain terms are written exactly as `docs/domain.md` spells them: `LeaveRequest`, `LeaveType`,
  `Balance`, `Allowance`, `approve`, `reject`, `cancel`. Never synonyms ("absence", "vacation", "booking").
- Files and folders: kebab-case (`leave-request.ts`). Types and React components: PascalCase.
  Functions and variables: camelCase. SQL tables and columns: snake_case.
- Tests sit next to the code: `<name>.test.ts(x)` for unit and component tests, and
  `<name>.int.test.ts` for API integration tests. The suffix is the fast/full selector
  (`docs/testing.md`), so it is never optional.
- Error codes: `UPPER_SNAKE`, prefixed with the rule they enforce where there is one (`BR2_INSUFFICIENT_BALANCE`).
- Branches and commits: `docs/git.md`.

## Error handling
- **Domain:** functions return a result value and never throw for a rule violation:
  `{ ok: true, value } | { ok: false, error: { code, message } }`. Throwing in `packages/domain`
  is reserved for programmer errors (impossible states).
- **API:** maps results to HTTP: `400` invalid input (zod), `401` no session, `403` forbidden
  action on a resource the caller may see, `404` not found **or belonging to someone the caller
  may not see** (`docs/security.md`), `409` rule conflict (overlap, insufficient Balance, final
  Status). The body is always `{ "code": string, "message": string }`.
- Unexpected errors return `500 { code: "INTERNAL", message: "Unexpected error" }` and are logged
  server-side without the request body. Stack traces, SQL and other users' data never reach a response.
- **Web:** shows the API `message` for 4xx responses and a generic message for 5xx. Every screen has an explicit error state.

## Data rules
- **Leave dates** are calendar dates with no time and no zone: ISO `YYYY-MM-DD` strings in the API,
  in SQLite (TEXT) and in the domain. `packages/domain` never builds a JS `Date` from local time;
  Working-day math uses UTC-only methods.
- **"Today"** is passed into domain functions as a `YYYY-MM-DD` parameter and is never read from the system clock in
  `packages/domain`. The API gets it from one injectable clock.
- **Day counts, Allowance, Balance:** integers (whole Working days). No half days, no floats.
- **IDs:** UUID v4 strings generated by the API (`crypto.randomUUID()`).
- **Timestamps** (created/decided at): UTC ISO-8601 with `Z`.
- **Status and Leave type** are stored as their exact domain spelling (`Pending`, `Annual`, …).

## Known traps
- `vitest` without `run` starts watch mode outside CI and never exits — always `vitest run` in scripts and check — from bootstrap.
- `new Date('2026-03-02')` parses as UTC midnight but `new Date(2026, 2, 2)` as local time: mixing them shifts leave dates by a day — keep dates as `YYYY-MM-DD` strings, use UTC methods only — from bootstrap.
- Native SQLite modules (e.g. `better-sqlite3`) need a compile step and break on Node major upgrades — prefer `node:sqlite`; any other driver needs an ADR — from bootstrap.
- ESM/CommonJS mixups (`require` in ESM, missing extensions) — everything is ESM; TS `moduleResolution: "nodenext"` for api/domain and `"bundler"` for web — from bootstrap.
- Only `VITE_*` env vars reach the browser bundle, and anything there is public — never put secrets in `VITE_*` — from bootstrap.
- Fastify `inject()` tests leave open handles unless the app is closed — `await app.close()` in `afterEach`/`afterAll` — from bootstrap.
- A new npm workspace without a Vitest project in `vitest.config.ts` runs its tests in neither check profile while check stays green — add the project; `tools/vitest-projects.test.ts` fails until you do — from spec 0001, review round 1 F-4.

## Design references
- A UI spec links a pinned Claude Design artifact (or a named waiver) as its Design reference. The rules
  and the exact line format are in `docs/testing.md`, "Design references (Claude Design artifacts)".
- The app's copy of the design system's tokens is `apps/web/src/styles/tokens.css`: values copied exactly, names unchanged,
  the source version in its header. Screens use only `var(--…)` from it, and base styles live in `apps/web/src/styles/base.css`.
  A design-system change reaches the app only through a `/change` that updates that header (spec 0003).

## Enforced by tooling
- **unit** step: the app's stylesheets (`apps/web/src/styles/styles.test.ts`, spec 0003): every `var(--…)` is defined in
  `tokens.css`, `base.css` has no literal colors, and the state → token mapping, column width and font fallbacks hold.
- **unit** step: open specs' Design references (`docs/testing.md`, Design references), checked by
  `tools/spec-design-reference.test.ts` (spec 0002).
- **format** step: Prettier (`.prettierrc.json`, 100 cols, single quotes) on all code and config files. Process Markdown is excluded (`.prettierignore`).
- **lint** step: ESLint recommended + typescript-eslint recommended + react-hooks, `--max-warnings=0`, and the
  forbidden dependencies of `docs/architecture.md`, including the ban on `Date.now()`, `Date()` and argument-less
  `new Date()` in `packages/domain` (`eslint.config.js`, proven by `tools/lint-boundaries.test.ts`).
- **typecheck** step: `tsc` per workspace with `tsconfig.base.json` (`strict`, `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `erasableSyntaxOnly`).
