## Risks & open questions
1. **jsdom computes no CSS.** Colors and layout can't be asserted in component tests. *Recommendation:* as decided in G3: the
   component tests assert `data-state`, a static stylesheet test asserts the state → token mapping, the 560px column, the gutter
   and that every `var()` is defined. VERIFY's before/after screenshots and a measured `scrollWidth ≤ 400` at 400px are the
   visual proof.
2. **Parsing CSS in a test without a dependency.** *Recommendation:* small regex reads over two hand-written files that the test
   owns (custom-property definitions, `var(--x)` uses, rule blocks by selector). No CSS parser package. If a selector becomes too
   complex for that, it's a review finding, not a reason to add a dependency silently.
3. **Google Fonts is a runtime request** from the browser (not from tests or check). *Recommendation:* accept as decided in G2. If
   the request fails, the system stacks render the page (CB-5), and VERIFY captures one screenshot with fonts blocked to show it.
4. **Hand-copied token values could drift** from the design system. *Recommendation:* accept with G1's header and the
   `docs/conventions.md` line. An automated sync would need network access in check, which `docs/testing.md` rules out.
5. **Environment (R-13):** doctor shows profile fast and full runnable on this machine, 0 fail / 0 warn. check.conf is unchanged.
   Locally check and doctor run via `dash` (B-1).
